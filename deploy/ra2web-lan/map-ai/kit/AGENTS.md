# 给地图制作 AI 的执行说明

目标：为 **Winlife RA2WEB 0.87.3，workshop7 或后续兼容版本** 制作可导入的真实地图，并交付可复查的验收证据。此包不需要模型 API、工作站账号或服务器密钥。

在线阅读时先下载并解压[完整制作包](https://ra.winlife.fun/map-ai/winlife-ra2-map-ai-1.0.0.zip)，文件散列见[下载信息](https://ra.winlife.fun/map-ai/download.json)。本地已经解压时直接执行以下步骤。

## 开始工作

1. 读取 [格式与 API](references/format-and-api.md)。按用户要求确定人数、地形、布局、资源和胜负玩法；未指定的普通设计选择可明确假设后继续。
2. 优先复制 `examples/` 的 JSON，修改设计。运行 `node scripts/generate.mjs 你的设计.json --out 新输出目录`。已有输出目录会被拒绝，避免覆盖已有地图。
3. 检查输出的真实 `.map`、`design.json`、`preview.svg` 和 `static-report.json`。修改设计后使用新的输出目录重跑。交付文件以报告中的 SHA256 绑定。
4. 按 [实际验收](references/acceptance.md) 在游戏中执行测试，记录截图、录制、网络校验值和实际观察。不能操作游戏的 AI，交付静态结果及待测清单即可，运行项保留 `pending`。

## 必须保持的格式约束

- 使用 `lib/map-codec.mjs` 编码，不编造 Base64 压缩串，不把概念图或 JSON 当成已完成的游戏地图。
- JSON 的 `position: [u,v]` 是可玩区域的归一化投影坐标。真实地图使用 `rx,ry`；`tileAtDisplay` 的第三参数是整行 `row`，不是半行 `dy`。通过 codec 换算。
- 真实出生点编号为 `0..N-1`；界面显示为 `1..N`。9–16 人必须有 `Basic.WinlifeMaxPlayers=N` 和 N 个独立有效的真实出生点。仅改 `MaxPlayer` 不会增加原生容量。
- 普通地图的 waypoint 8 及以上可以是任务路点；修改导入图时先识别容量标记，保留普通路点和未知配置。
- 静态自动验收范围是温带/雪地、平地、水域、矿物、已核实树木和中立建筑的标准陆战地图。坡道、悬崖、桥梁、战役脚本、规则覆盖和海战图需要额外的原生规则与运行验证；不要为获得通过而删除用户要求的内容或放宽校验器。
- 水域画笔不自动生成岸线；直接升高地块也不会生成可通行坡道。对复杂地形先核实瓦片组合及实际通行，不能只看颜色相邻。

## 验收用语与证据

- `static-pass-runtime-pending` 表示格式、原生数据解码和有限的设计近似检查通过。它不表示已进入游戏。
- `preview.svg` 是从地图数据绘制的示意图，不是游戏截图。
- 对每一项运行测试记录 `pass / fail / pending`、观察及证据路径。未执行、无法访问、未看见的项目写 `pending`；加载页面、能解析和画面相似不能代替开局、寻路和状态一致性检查。
- 原生解码快照只执行 INI/压缩/地块/覆盖物/路点/出生点数据路径，覆盖范围和跳过的方法见 `SOURCES.json`。不要把它描述成完整游戏模拟。
- 地图文件变化后重算 SHA256，重新生成静态报告；旧文件的运行证据不能直接套用到新文件。

## 最终交付

交付 `.map`、可复现设计 JSON 或生成脚本、数据预览、静态报告、运行验收 JSON 及已有证据。说明目标客户端、MOD、实际验证范围、已知问题及待测项。例图目前只作为制作示例，不能因示例静态通过而给新的生成图标记实战通过。

发布地图库是后续独立操作。本制作包默认只在指定输出目录生成文件，不修改游戏客户端、联机服务或公共地图索引。
